# 장애 대비와 복구

## 앱이 안 될 때 가족이 할 일 (미리 공유)

1. 기다리지 말고 **전화·문자**로 안부를 알린다. 위급하면 119·112.
2. 연락이 안 되면 **1순위 집합장소**로 간다. 시간이 지나면 다음 순위로.
3. 집합장소와 전화번호는 **인쇄용 비상카드**를 본다 (더보기 → 인쇄용 비상카드). 미리 인쇄해 지갑과 배낭에 둔다.
4. 화면이 이상하면 앱을 닫았다 다시 연다. **로그아웃하거나 앱을 지우지 않는다** (보관된 신고가 사라질 수 있다).

## 1분 점검

```bash
node tools/health-check.mjs
```

읽기만 한다. 매시간 GitHub Actions "서비스 상태 점검"도 같은 것을 돌린다. 푸시가 실제로 오는지는 이 점검으로 알 수 없으니
**한 달에 한 번 테스트 알람**을 보내고 확인 현황을 본다 (관리자 설정 → 테스트 경보).

## 증상별 조치

| 증상 | 먼저 볼 것 | 조치 |
|---|---|---|
| 사이트가 안 열림 | 점검의 "사이트" 항목, <https://www.githubstatus.com> | GitHub 장애면 기다린다 (열어 본 휴대폰은 저장본으로 열린다). 배포 직후면 **사이트 되돌리기** |
| 새 버전이 휴대폰에 안 옴 | "사이트 파일 전부" | 없는 파일이 있으면 사이트 되돌리기 |
| 로그인 안 됨 | "알림 서버" 항목 | 배포 직후면 **알림 서버 되돌리기**. 코드를 3번 틀린 것이면 관리자 설정 → 접속 잠금에서 풀기 |
| 비상 알림이 아무에게도 안 옴 | 관리자 기록의 발송 결과, `npx wrangler tail` | 먼저 전화·문자. 배포 직후면 알림 서버 되돌리기 |
| 한 사람만 알림이 안 옴 | 그 휴대폰의 설정 → 알림 | 알림 켜기 → 테스트 알림. 아이폰은 홈 화면 아이콘으로 열기 |
| 알림이 계속 반복됨 | 관리자 기록의 "N번째 발송" | 관리자가 비상을 해제. 그래도 오면 알림 서버 되돌리기 |
| 재난문자 오경보가 반복됨 | 관리자 설정 → 정부 재난문자 자동 경보 | 자동 경보 끄기, 비상 해제 |
| 저장이 안 됨 / HTTP 429 | Firebase 콘솔 → 사용량 | 무료 한도는 태평양 시각 자정에 초기화. 그동안 전화·문자 |
| 가족 정보가 밖에서 보임 | "가족 정보가 밖에서 보이지 않음" | 바로 Firebase 콘솔 → Firestore → 규칙에 `firestore.rules` 다시 게시 |

## 되돌리기

### 사이트

문제가 된 병합 커밋을 되돌려 올리면 몇 분 안에 다시 배포된다.

```bash
git fetch origin && git switch -c revert-site origin/main
git revert -m 1 <병합 커밋>
npm test
git push -u origin revert-site   # PR 을 만들어 main 에 합친다
```

정상이던 사이트 버전: `27338c4` (PR 23까지), `d57146d` (화면 정리 전).
휴대폰은 앱을 닫았다 다시 열면 되돌린 버전을 받는다.

### 알림 서버

```bash
cd worker
npx wrangler deployments list
npx wrangler rollback adf9dcf5-ae52-40f1-94e9-2dff9c1e209e
```

`adf9dcf5…` 는 2026-10-29 에 배포된, PR 24 전의 버전이다. **새로 배포하기 직전에 지금 버전 id 를 적어 둔다.**
되돌려도 데이터는 그대로다. 예전 서버는 `notifyState` 를 쓰지 않을 뿐이고, 사이트와 서버는 어느 쪽이 먼저 바뀌어도 함께 동작한다.

## 배포 순서 (문제를 빨리 알아채게)

1. `node tools/health-check.mjs` 가 정상인지 본다. 알림 서버 버전 id 를 적는다.
2. 사이트를 합치고 점검을 다시 돌린다. 내 휴대폰으로 열어 본다.
3. `cd worker && npx wrangler deploy` 뒤 점검을 다시 돌린다. `npx wrangler tail` 로 1분 실행에 오류가 없는지 5분 본다.
4. 가족에게 미리 알리고 테스트 알람을 보낸다.
5. 하나라도 이상하면 위의 되돌리기를 먼저 하고 원인을 찾는다.
