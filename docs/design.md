# 가족 비상 연락망 — 설계 문서

작성일: 2026-10-27

## 목적

전쟁, 자연재해, 전염병 같은 비상 상황에서 가족이 서로의 안전을 확인하고 다시 모이기 위한 웹사이트.
가족 누구나 휴대폰으로 열고, 가장 먼저 "나 무사해요"를 눌러 생존신고를 한다.

## 사용자가 정한 것

| 항목 | 결정 |
|---|---|
| 첫 화면 | "나 무사해요" 버튼. 누르면 GPS 위치와 시간이 같이 기록된다 |
| 호스팅 | GitHub Pages(무료), 저장소는 공개, 코드만 담는다 |
| 데이터 | Firebase 무료 요금제(Spark) |
| 알림 서버 | Cloudflare Workers 무료(카드 등록 없이) |
| 로그인 | 가족마다 각자 비밀번호 |
| 권한 | 관리자 / 일반 가족. 관리자는 여러 명 가능 |
| 관리자 기능 | 가족 추가·수정·삭제, 모든 가족의 위치와 기록 열람 |
| 비상선언 | 관리자가 선언하면 알림이 울린다. 일반 가족도 1회 선언 가능 |
| 집합장소 | 1~10순위, 각 순위마다 장소와 시간. 시간이 지나면 다음 순위로. 집합장소에 기록을 남길 수 있다 |
| 집합 시간 | 평소에는 "비상 발생 후 N시간"으로 정해 두고, 선언 순간 실제 날짜·시간으로 계산된다 |
| 프로토콜 | 상황별 대처법과 체크리스트 |
| 개인정보 | 성별, 혈액형, 나이, 전화번호, 이메일, 집주소 등 |
| 인원 | 최대 20명, 모두 휴대폰 사용 |
| 보안 점검 | GitHub의 자가진단 도구 사용 |

## 제가 정한 것 (확인 필요)

- **가족 간 공개 범위.** 일반 가족은 다른 가족의 이름, 전화번호, 마지막 생존신고(상태·시간·위치)를 볼 수 있다. 가족을 찾는 게 목적이므로 마지막 위치는 공유한다. 생년월일·나이, 성별, 혈액형, 이메일, 주소, 의료 메모와 전체 위치 기록은 본인과 관리자만 본다.
- **계정.** 아무나 가입할 수 없다. 관리자가 이메일과 첫 비밀번호로 계정을 만들어 주고, 가족은 로그인 후 비밀번호를 바꾼다. 한 번 로그인하면 로그아웃할 때까지 유지된다(비상시 비밀번호를 잊어도 열리도록).
- **첫 관리자.** 사이트를 처음 연 사람이 "초기 설정"으로 첫 관리자가 된다. 설정이 끝나면 이 경로는 영구히 닫힌다. 배포 직후 바로 해야 한다.
- **생존신고 종류.** "나 무사해요"(기본), "도움 필요", "체크포인트 저장"(메모 포함) 세 가지. 모두 GPS 위치와 시간을 남긴다.
- **일반 가족의 비상선언.** 1회 권한을 쓰면 0이 되고, 관리자가 다시 채울 수 있다. 누가 선언했는지 표시되고, 관리자만 비상을 해제할 수 있다. 이미 비상 중일 때는 덮어쓸 수 없다.
- **집합 시간 계산.** 각 순위는 "선언 후 N시간"과 "대기 시간(분)"을 가진다. 지금 가야 할 곳은 "도착 시간 + 대기 시간"이 아직 지나지 않은 가장 높은 순위다. 관리자는 비상 중에 특정 순위의 시간을 실제 날짜·시간으로 직접 바꿀 수 있다.
- **체크리스트 상태**는 사람마다 따로 저장되고, 관리자는 가족별 진행률을 본다.
- **프로토콜 초안.** 기본 원칙, 전쟁·공습, 화생방·핵, 지진, 태풍·홍수, 화재, 감염병, 정전·통신두절을 기본으로 넣는다. 관리자가 수정·추가할 수 있다. 서버에 아무것도 없을 때도 앱에 내장된 기본값이 보인다.
- **알림.** Firebase Cloud Messaging(FCM) 웹 푸시. 아이폰은 홈 화면에 추가해야 받을 수 있다. 사이트가 열려 있으면 1급 비상에서 경보음(사이렌)과 진동을 낸다. 2급은 화면 알림만.
- **문자 대체 수단.** 데이터가 끊기고 문자만 될 때를 위해 "문자로 알리기" 버튼이 가족 전화번호와 내 좌표가 담긴 문자 작성 화면을 연다.
- **인쇄용 비상카드.** 집합장소와 가족 연락처를 종이로 출력해 지갑·배낭에 넣을 수 있다.
- **지도.** Leaflet + OpenStreetMap(무료, 키 불필요). 길찾기는 카카오맵·네이버지도·구글지도 앱으로 연결한다.

## 구조

```
web/        GitHub Pages로 배포되는 정적 사이트 (빌드 없음, ES 모듈)
worker/     Cloudflare Worker (알림 발송, 계정 삭제·비밀번호 초기화)
firestore.rules, firestore.indexes.json, firebase.json   Firebase 설정
tests/      순수 로직 단위 테스트(node --test), 보안 규칙 테스트(에뮬레이터)
.github/    Pages 배포, 테스트, CodeQL, Dependabot
```

### 데이터 (Firestore)

| 경로 | 내용 | 읽기 | 쓰기 |
|---|---|---|---|
| `members/{uid}` | 이름, 전화, 역할, 활성, 선언권 횟수, 마지막 신고 | 가족 | 관리자 / 본인은 마지막 신고·전화·선언권 1 차감만 |
| `profiles/{uid}` | 성별, 생년월일, 혈액형, 이메일, 주소, 의료 메모 | 본인, 관리자 | 본인, 관리자 |
| `checkins/{id}` | 생존신고·체크포인트 기록 | 본인, 관리자 | 본인 생성만 (수정 불가) |
| `emergency/current` | 비상 상태(종류, 메시지, 선언자, 선언 시각) | 가족 | 관리자 / 가족은 선언권이 있을 때 선언만 |
| `emergencyLog/{id}` | 선언·해제 기록 | 가족 | 가족(본인 명의 생성만) |
| `meetingPoints/{1..10}` | 집합장소 | 가족 | 관리자 |
| `meetingLogs/{id}` | 집합장소에 남긴 기록 | 가족 | 본인 명의 생성 |
| `protocols/{id}` | 프로토콜 | 가족 | 관리자 |
| `checklists/{uid}` | 체크리스트 상태 | 본인, 관리자 | 본인 |
| `pushTokens/{token}` | 알림 토큰 | 본인 | 본인 |
| `config/setup` | 초기 설정 완료 표시 | 로그인한 사람 | 최초 1회만 |

### 비상 시 안정성

- 화면: GitHub Pages(전 세계 CDN), 데이터: Google Firebase, 알림: Cloudflare. 셋 다 대형 인프라이고 서로 독립적이다.
- 서비스 워커가 앱 화면, 라이브러리, 프로토콜 기본값, 본 지도 타일을 휴대폰에 저장한다. 한 번 열어 본 휴대폰은 인터넷 없이도 열린다.
- Firestore 오프라인 저장소를 켠다. 인터넷이 없을 때 누른 생존신고는 휴대폰에 쌓였다가 연결되면 자동으로 전송된다. 가족 정보·집합장소도 마지막으로 받은 내용이 보인다.
- 문자 대체 수단과 인쇄용 비상카드.

### 보안

- 모든 권한 검사는 Firestore 보안 규칙(서버)에서 한다. 화면의 버튼 숨기기는 편의일 뿐이다.
- 비밀 키(서비스 계정)는 Cloudflare Worker 비밀 변수에만 둔다. 저장소에는 공개돼도 되는 Firebase 웹 설정만 들어간다.
- Worker는 Firebase ID 토큰을 직접 검증하고, Firestore에서 역할을 다시 확인한다. 알림은 비상 상태가 바뀌었을 때 한 번만 보낸다(남용 방지).
- 콘텐츠 보안 정책(CSP)으로 허용된 출처의 스크립트만 실행. 외부 라이브러리는 버전 고정 + SRI 해시.
- 사용자 입력은 절대 HTML로 넣지 않는다(textContent만 사용).
- GitHub: CodeQL 코드 스캔, Dependabot, 비밀 스캔과 푸시 차단, OpenSSF Scorecard.

## 2차 변경 (2026-10-27)

사용자 요청:
- 관리자 모드에서 알림 기록과 관련 기록을 한 번에 본다.
- 아이디와 비밀코드로 접속한다.
- 화면을 국가 사이트처럼 → 이후 "미국 국가 시스템 느낌"으로 변경 요청.
- 내용 구성을 더 알차고 고급스럽게.
- 오프라인에서도 GPS로 위치를 확인한다.
- 관리자는 가족 정보를 한 번에 보고, 각 가족은 최대 3명의 정보만 본다.

제가 정한 것:
- **로그인**: 아이디는 영문 소문자·숫자 3~20자. Firebase 로그인은 이메일 형식이 필요하므로 내부적으로 `아이디@프로젝트ID.firebaseapp.com`로 바꿔 쓴다(메일은 오가지 않음). 비밀코드는 6자 이상, 너무 쉬운 조합은 거부. 이전 방식(이메일) 계정도 그대로 로그인된다. 아이디 계정은 비밀코드 재설정 메일을 받을 수 없어 관리자가 초기화한다.
- **공개 범위**: `members.links`(최대 3명, 관리자만 지정)에 있는 가족만 `members`·`profiles` 문서를 읽을 수 있다. 전체 목록(list)은 관리자만. 위치 기록 전체와 체크리스트는 지금처럼 본인·관리자만. 집합장소 게시판은 모이기 위한 공지판이라 가족 전체가 본다.
- **관리 기록**: `auditLog` 컬렉션. 관리자 작업은 같은 일괄 쓰기 안에서 기록이 남고(규칙상 관리자만, 수정·삭제 불가), 알림 발송 결과는 Worker가 서비스 계정으로 남긴다. 관리자 기록 화면은 비상 기록·생존신고·집합 기록·관리 기록을 하나의 시간순 목록으로 합치고, 종류·가족·기간·검색으로 거르고 CSV로 내려받는다(엑셀 수식 실행 방지 처리).
- **디자인**: USWDS 디자인 언어(Public Sans + Pretendard, 남색·파랑, 왼쪽 색 띠 알림, 단계 표시, 처리 목록, 요약 상자, 표). 정부 배너·문장은 쓰지 않는다. 글자 크기 3단계(설정 화면).

- **오프라인 GPS**: 오프라인이면 정밀 위치를 최대 60초 기다리고, 실패하면 마지막 위치를 보여준다. 집합장소까지 직선 거리·방위(8방향)·도보 시간을 지도 없이 계산한다. 실시간 추적은 화면을 떠나면 멈춘다.
- **내용**: 대처법 15가지(폭염, 한파·폭설, 산사태, 지진해일, 인파 밀집 사고, 가족과 떨어졌을 때 추가)와 각 "꼭 기억할 것" 3가지. 비상 연락처 화면(공공 번호 11개 + 관리자가 관리하는 가족 지정 연락처), 사용 안내 화면.

## 3차 변경 (2026-10-27)

사용자 요청:
- 상단 안내 띠와 "정부기관과 무관" 문구를 없앤다.
- 경보를 경계 → 실제 2단계로, 테스트 알람도 할 수 있게.
- 영어로도 바꿀 수 있게. 보안 점검과 전체 오류 검토.
- 저장된 관리자를 초기화하고, 접속 코드를 3가지(관리자용, 일반 가족용, 백업용)로. → 사용자가 "공용 코드 3개 + 이름 고르기", "백업 코드로 앱에서 초기화"를 골랐다.
- 인터넷이 안 될 때도 동작하도록 설치할 때 미리 준비.

제가 정한 것:
- **접속 코드**: 코드마다 "관문 계정"(Firebase 이메일/비밀번호 계정)을 하나씩 두고, 코드가 그 비밀번호다. 코드를 넣으면 가족→관리자→백업 순서로 관문 계정 로그인을 시도한다. 관문 계정은 이름 목록(`access/family`, `access/admin`)만 읽을 수 있다. 목록에는 각 사람 계정의 무작위 열쇠가 들어 있어, 이름을 고르면 그 사람 계정으로 바꿔 로그인한다. 그래서 "지정된 3명만 보기" 같은 사람별 규칙이 그대로 서버에서 지켜진다.
- **코드 바꾸기**: 새 관문 계정을 만들어 `public/gates` 에서 바꿔 끼운다. 예전 코드를 몰라도 되고, 예전 코드는 즉시 무효. 백업 코드로는 관리자 코드 교체와 관리자 추가만 할 수 있다.
- **초기화**: 처음 설정 때 세대(`gen`)를 새로 정한다. 세대가 다른 가족 문서(예전 아이디 방식 계정)는 규칙·Worker에서 모두 거부되고, 관리자 설정 화면에서 정리할 수 있다.
- **경보 단계**: `emergency/current.level` = `alert`(경계, 4차에서 "2급") | `real`(실제, 4차에서 "1급"). 집합 시간은 실제가 된 시각(`realAt`)부터. 경계 → 실제 전환은 관리자 또는 선언권이 남은 가족.
- **테스트 알람**: `alarmTests` 문서. 보낸 지 30분 안에 연 휴대폰에서 "테스트" 표시와 함께 울리고, 확인을 누르면 `acks/{uid}` 가 남아 관리자가 누가 확인했는지 본다. 실제 경보 상태는 바뀌지 않는다.
- **영어**: 한국어 원문을 키로 쓰는 `t()` 번역(`web/js/i18n.js`, `i18n/en-*.js`). 대처법 15개와 공공 연락처는 영어판 데이터 파일. 관리자가 직접 추가한 대처법은 입력한 언어 그대로. 푸시 알림 문구는 한국어.
- **오프라인 준비**: 들어올 때(하루 한 번, 집합장소가 바뀔 때, 앱 설치 순간) 저장 공간 고정 요청과 집합장소·내 위치 주변 지도(줌 12~16) 미리 받기. 설정 화면에서 상태 확인과 "지금 준비하기"(위치 권한 요청 포함).
- **보안 점검 반영**: 기록의 이름을 본인 이름으로 강제, 비상 기록은 실제 변경과 같은 일괄 쓰기에서만, 집합장소 게시판에 위치 좌표를 남기지 않음, 체크리스트·날짜 필드 형식 검사, Worker는 사람마다 최근 기기 2대에만 발송하고 한 기기 실패가 전체를 막지 않게, 서비스 워커는 앱 첫 화면만 오프라인 화면으로 저장, 배포본 CSP에서 에뮬레이터 주소 제거.


## 4차 변경 (2026-10-27)

요청:
- 관리자 페이지에서 비상을 빠르게 선언할 수 있게.
- 1급(지진, 전쟁, 대형재난)은 경보음 + 알림, 2급(준위험)은 알림만.
- 알림이 잘 되는지 전체 테스트.

제가 정한 것:
- **1급·2급은 기존 2단계에 맞췄다**: 2급 = `level: 'alert'`(예전 "경계"), 1급 = `level: 'real'`(예전 "실제"). 저장 형식과 보안 규칙은 그대로이고, 2급 → 1급 격상과 "1급부터 집합 시간 시작"도 그대로다.
- **소리**: 1급만 사이렌(파상음)을 낸다. 2급은 화면 알림만 띄운다(소리·진동 없음). 2급용 평탄음은 없앴다. 푸시 알림도 1급은 닫을 때까지 화면에 남고 길게 진동, 2급은 보통 알림.
- **빠른 비상 선언**: 관리자 홈 화면 맨 위와 비상 경보 화면에 상황 버튼. 1급: 지진, 전쟁·공습, 대형재난(새 상황 종류 `disaster`), 화생방·핵. 2급: 태풍·홍수, 화재·산불, 폭염, 한파·폭설, 정전·통신두절, 감염병, 기타. 버튼 → 확인 한 번 → 발령. 메시지를 붙이려면 기존 발령 양식을 쓴다.
- **테스트 알람**: 소리 선택이 "1급(경보음 + 알림)" / "2급(알림만)"이 되었다. 2급 테스트는 소리 없이 뜬다.

## 5차 변경 (2026-10-27)

요청:

- 관리자 기능 추가, 소리 테스트.

제가 정한 것:
